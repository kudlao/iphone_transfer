# Hush Photo

**Экспорт фотографий и видео с iPhone на Windows без облачной передачи**

[Русский](README.md) · [English](README_EN.md) · [简体中文](README_ZH.md)

![Hush Photo — обзор интерфейса и возможностей](hush-photo-overview.png)

Hush Photo — бесплатное приложение с открытым исходным кодом для переноса медиафайлов с iPhone на компьютер с Windows 10/11 (x64). Оно читает доступные файлы через USB и Apple File Conduit (AFC), позволяет просматривать медиатеку, выбирать нужные фотографии и видео, сохранять оригиналы и продолжать прерванный экспорт.

Проект также поддерживает обработку медиафайлов из обычной папки на компьютере. **Hush Photo не является средством полного резервного копирования iPhone.**

**Примеры интерфейса:** [подключение iPhone, медиатека и параметры экспорта](docs/INTERFACE.md).

## Возможности

- **Фото и видео:** экспорт HEIC, HEIF, JPEG, PNG, TIFF, DNG, MOV и MP4; видео копируются без перекодирования. Поддерживаются также файлы AAE на уровне обнаружения через AFC, но интерфейс не предлагает их для отдельного экспорта.
- **Live Photos:** экспорт фотографии вместе с соответствующим MOV. Сопоставление выполняется по имени и расположению файлов, а не по внутреннему идентификатору Apple.
- **Автоматическое подключение:** при доступности утилит USB-обнаружения приложение находит подключённый iPhone и запускает сканирование; ручной поиск остаётся резервным вариантом.
- **Медиатека:** автоматическая подгрузка миниатюр во время прокрутки, поиск по имени, просмотр страницами по 36 файлов и раздельный выбор фото и видео.
- **Фильтры видео:** «Все видео», «Видеоролики» и «Live Photos». Экспортируются только выбранные файлы текущего фильтра; выбор других категорий сохраняется.
- **Повторный экспорт:** проверка уже сохранённых файлов, пропуск подтверждённых копий, безопасная обработка одноимённых файлов и отмена операций.
- **Организация:** сохранение исходной структуры DCIM, одна папка или группировка по месяцу съёмки (когда дата доступна).
- **Интерфейс Windows:** автоматическая светлая или тёмная тема, состояние подключения, ход передачи, скорость и приблизительное оставшееся время.

## Системные требования

| Компонент | Требование |
| --- | --- |
| Операционная система | Windows 10/11, x64 |
| iPhone | Разблокированное устройство с подтверждённым доверием к компьютеру |
| USB-доступ | Apple Mobile Device Support и совместимый набор libimobiledevice для Windows |
| Запуск из исходников | Python 3.11 x64 рекомендуется; зависимости из `requirements.txt` |
| Portable | Полная папка `HushPhoto` из собранного архива; Python на целевом ПК не нужен |

**Важно для USB-экспорта:** необходимы Apple Mobile Device Support и совместимый набор libimobiledevice для Windows. Способы указания пути к установленным USB-утилитам и библиотекам описаны ниже, в разделе [«Настройка USB-утилит»](#настройка-usb-утилит).

На Windows установите Apple Devices либо другой официальный компонент Apple, предоставляющий Apple Mobile Device Support. Сторонние программы и драйверы могут влиять на доступность устройства.

### Настройка USB-утилит

Для доступа к фотографиям требуется `afcclient.exe` и совместимые библиотеки из **одной** сборки libimobiledevice. Для автоматического определения подключения рекомендуется также `idevice_id.exe`. Не смешивайте EXE и DLL из разных наборов.

Предусмотрены три способа настройки:

1. **Portable или исходный код:** поместите инструменты в папку `native` рядом с `HushPhoto.exe` либо рядом с `iphone_usb.py` при запуске из исходников.
2. **Переменная окружения:** укажите каталог с инструментами перед запуском:
   `$env:HUSH_AFC_TOOLS = 'D:\Tools\libimobiledevice'`
3. **Системный PATH:** добавьте каталог с `afcclient.exe` в `PATH` и перезапустите приложение.

Указывайте **папку**, не полный путь к исполняемому файлу. Пример проверки в PowerShell из каталога утилит:

```powershell
.\idevice_id.exe -l
.\afcclient.exe ls /DCIM
```

Первая команда должна показать идентификатор подключённого устройства, вторая — доступные каталоги DCIM. При недоступности автоматического определения можно запустить сканирование вручную из приложения.

## Использование

1. Подключите iPhone по USB, разблокируйте его и при запросе нажмите **«Доверять»**. Hush Photo проверяет подключение в фоновом режиме и начинает сканирование автоматически. При необходимости используйте кнопку проверки подключения или «Обновить».
2. Переключитесь на **«Фото»** или **«Видео»**. Для видео выберите подкатегорию; для поиска введите часть имени файла. Прокрутка и переключение страниц автоматически загружают нужные миниатюры фотографий.
3. Отметьте файлы. **«Выбрать всё»** и **«Снять выбор»** применяются к текущему фильтру поиска; скрытые поиском выбранные файлы сохраняются. Число выбранных файлов показывается под заголовком медиатеки.
4. Нажмите **«Выбрать папку назначения»**, затем **«Экспортировать»**. В открывшемся окне проверьте параметры и нажмите **«Начать экспорт»**.
5. Во время переноса доступны прогресс, текущий файл, скорость, приблизительный ETA и отмена. После завершения медиатека остаётся открытой, если соединение не было потеряно.

Для работы с уже сохранённой папкой переключите источник с **«iPhone»** на **«Папка»**. Исходная и целевая папки не должны совпадать или находиться одна внутри другой.

### Параметры экспорта

| Режим | Результат |
| --- | --- |
| **Оригиналы** (по умолчанию) | Сохранение исходных файлов без перекодирования |
| **Оригиналы + JPEG** | Оригинал и JPEG-копия для совместимости |
| **JPEG** | JPEG-копии фотографий; **при USB-экспорте оригинал также сохраняется** |
| **TIFF** | TIFF-копии фотографий; **при USB-экспорте оригинал также сохраняется** |
| **Видео** | MOV/MP4 копируются в исходном формате |

Для создания JPEG доступна настройка качества (85–100; по умолчанию 97). JPEG — формат с потерями; преобразование HDR в SDR не обеспечивает полноценного tone mapping. Для архивного хранения выбирайте оригиналы.

Параметр **«Сохранить движение Live Photos (MOV)»** добавляет видео к выбранной фотографии, если найдена пара с тем же именем в той же папке. При отдельном экспорте видео этот параметр не требуется.

**Структура каталогов:**
- **По годам и месяцам:** `YYYY-MM` по доступной дате съёмки; при её отсутствии — папка `Без даты`.
- **Оригинальная структура:** сохранение относительного пути из источника (включая DCIM при USB-экспорте).
- **Одна папка:** файлы сохраняются в выбранном каталоге с безопасным разрешением совпадающих имён.

## Надёжность и хранение данных

Hush Photo не изменяет содержимое iPhone. Экспорт выполняется через временные файлы с последующим переносом в конечный каталог, чтобы незавершённая передача не заменяла ранее сохранённый оригинал.

При **USB-экспорте** приложение ведёт реестр `.hushphoto-manifest.json` и отчёт `hushphoto_last_export.json` в целевой папке. Повторная операция проверяет размер и SHA-256 локального файла и пропускает подтверждённые копии. Это **не** независимая проверка SHA-256 содержимого на iPhone. При **экспорте из папки** повторные копии сравниваются по SHA-256; отчёт записывается в `export_report.txt`.

Миниатюры создаются локально и временно сохраняются в `%LOCALAPPDATA%\HushPhoto\previews`. Они подгружаются по мере просмотра и очищаются при нормальном закрытии приложения. Остатки после аварийного завершения очищаются при следующем запуске. Временный оригинал, необходимый для создания миниатюры, также удаляется. **Очистка кэша не затрагивает экспортированные файлы.**

## Ограничения

- AFC предоставляет не всю библиотеку приложения «Фото». Фотографии, доступные только в iCloud, могут не присутствовать на устройстве. Число файлов DCIM может отличаться от числа объектов в «Фото».
- Принадлежность файлов к альбому **«Недавно удалённые»** не определяется надёжно через AFC; приложение не удаляет их и не обещает исключить из результатов.
- Определение MOV-компонентов Live Photos по имени и каталогу является эвристическим.
- Для видео не создаются миниатюры предпросмотра; они представлены карточками с типом файла.
- При потере USB-соединения потребуется повторное сканирование. Продолжение экспорта относится к завершённым и проверенным копиям, а не к середине незаконченного файла.
- Portable-сборка не включает `libimobiledevice` автоматически, если набор инструментов не предоставлен при сборке.

## Запуск, тестирование и сборка

**Из исходного кода:**

```powershell
.\start_windows.bat
```

Скрипт установит недостающие Python-зависимости и откроет Hush Photo. Для прямого запуска после установки зависимостей: `py modern_ui.py`.

**Тесты:**

```powershell
py -m unittest -q tests_next tests_preview_cache test_media_groups tests_iphone_scan test_ui_smoke
```

GUI-тестам нужен интерактивный сеанс Windows. Для проверки реального USB-экспорта необходим физический iPhone.

**Portable-сборка на своём компьютере (Windows):**

Перед сборкой положите совместимые `afcclient.exe` и DLL в папку `native` в корне проекта (желательно вместе с `idevice_id.exe`) либо укажите каталог через `HUSH_AFC_TOOLS`. Для доступа к iPhone также требуется Apple Mobile Device Support.

```powershell
.\build_portable.bat
```

Скрипт локально создаёт окружение Python, устанавливает зависимости, запускает тесты и собирает `dist\HushPhoto` и `dist\HushPhoto-Windows-Portable.zip`. Готовый пакет переносится **целиком**: одного EXE недостаточно. Если AFC-инструменты не предоставлены, ZIP всё равно создаётся, но экспорт с iPhone по USB работать не будет. Перед пересборкой закройте `HushPhoto.exe`.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| iPhone не определяется | Кабель, разблокировку, доверие компьютеру, Apple Mobile Device Support, `idevice_id.exe -l` |
| Сканирование не начинается | Наличие `afcclient.exe` и DLL, настройку `native` / `HUSH_AFC_TOOLS` / `PATH`; попробуйте ручной поиск |
| Сканирование прерывается | Повторно подключите iPhone; проверьте, что он разблокирован и доступна папка DCIM |
| Фото не отображается | Файл может находиться только в iCloud или его миниатюра не может быть прочитана; оригинал может оставаться доступным для экспорта |
| Перенос прерван | Повторите экспорт в ту же папку: проверенные копии будут пропущены |
| Проблемы воспроизведения HDR/HEVC | Проверьте оригинальное видео в проигрывателе с поддержкой соответствующего кодека |
